Most important corrections

1. Do not classify a Node S 'exit' callback as missing-final failure immediately. FD4 can still contain an unread valid final record when S exits. Mark S exited, stop sending commands, close B control, and boundedly drain FD4 to EOF (or a distinct short status-drain deadline), validating the complete stream. Only then decide missing/malformed final versus valid final. Do not destroy FD4 in the exit handler and discard queued evidence. Likewise, a final record does not prove S itself has exited; bound its expected exit, report S-stall uncertainty separately, and never kill S as a cleanup shortcut. This is separate from the 250 ms stdout/stderr drain budget. Node explicitly distinguishes exit from closed stdio and close waits for shared streams: [Node ChildProcess events](https://nodejs.org/api/child_process.html#event-exit).

2. The grammar cannot require READY before every FINAL: spawn failure, profile rejection, early gate EOF and startup timeout legitimately need FINAL without READY. Allow exactly optional READY then exactly FINAL; never READY after cancellation/final, duplicates, unknown fields, bad types, oversized lines, trailing garbage or unterminated EOF. Apply bounded framing to stream bytes, not read/write calls. Suggested small budget: <=1 KiB per newline-delimited UTF-8 record, <=2 records and <=2 KiB total; freeze schema v1. READY means the post-Seatbelt gate is blocked and root ownership/group/observation are established, not that requested exec succeeded. FINAL distinguishes spawnSucceeded, releaseIssued, rootExitObserved, rootReaped, cleanupUncertain and actual exit/signal/errors. No host paths or numeric PID/PGID/SID need leave S; gate identity is private S<->C setup data.

3. Never pass request.signal, Node timeout, or killSignal options to spawn(S): those can kill S through Node's child machinery. Send only G/A over FD3, and maintain B-side receipt deadlines that close control/report uncertainty rather than kill S/C. Existing seatbelt-backend.js:740–756,846–855 numeric group signaling must leave the JS macOS execution path; do not leave its finalizer active alongside native ownership. ChildProcess PID now names S, so old code would target the wrong group. Existing process-io.js:35–47 associates stdin availability with S.exitCode: replace that association with the native execution state and invalidate stdin on final/uncertainty. Keep abort/disposal tracking through both native receipt and bounded output draining.

4. Make every setup/observation API failure a transition, not just a failed assertion. posix_spawn/file-action/attribute APIs return error numbers directly; waitid/waitpid/kill/read/write use their normal -1/errno conventions. Save errors immediately. After successful spawn, record and own C before any subsequent operation; pre-ready cleanup can signal only that unreaped direct C. Failed NOTE_EXIT registration may use a previously validated WNOWAIT fallback, otherwise abort. ECHILD means the reservation is lost: permanently stop numeric signaling immediately and report uncertainty. An unexpected waitid observation error is not permission to release. Do not use waitpid(-1), SIGCHLD=SIG_IGN or SA_NOCLDWAIT.

5. A fixed 250 ms settle cannot guarantee a waitable/reaped child. After the last authorized signal, latch off all signals and timers permanently. Reap only when waitability is known, with a bounded/nonblocking wait and bounded EINTR handling. If still not waitable or reap fails, emit cleanupUncertain/rootReaped=false, retire the numeric target and exit (or explicitly design a separate bounded reap-only phase); do not block indefinitely or claim cleanup. No new numeric cleanup authority can be recovered after S exits. Group KILL success does not prove all members died; EPERM/ESRCH must retain their actual meaning rather than become an enumeration fallback. Prior probes already observed EPERM against an exited-root-only group.

Transport and descriptor plan

The five Node stdio entries are appropriate, but describe FD3/4 as directional protocol use of inherited byte streams, not guaranteed anonymous unidirectional pipes. Upstream libuv v1.51.0 uv__process_init_stdio uses SOCK_STREAM socketpairs for UV_CREATE_PIPE; its spawn handling also distinguishes child blocking stdio and parent nonblocking endpoints. This is corroborating source, not a runtime measurement: [libuv process.c](https://raw.githubusercontent.com/libuv/libuv/v1.51.0/src/unix/process.c). Node also documents that these are not ordinary Unix pipes: [Node stdio](https://nodejs.org/api/child_process.html#optionsstdio).

B owns the peer endpoint that can send on the FD3 connection; S also has a socket endpoint, but its unused write half is not a leaked B peer. S reads only FD3 and writes only FD4. Do not call .end() on B control after G: write-half closure is cancellation even if B remains alive. A should be followed by ending/destroying control as a backstop; cleanup does not depend on the A write callback. S must read buffered bytes and handle short reads/EINTR/EAGAIN, EOF, reset and poll errors. For coalesced G+A or G+EOF in one bounded drain, terminal cancellation wins before issuing gate release. A/EOF observed only after release still means cleanup; no atomic transaction prevents execution during the concurrent-close race. State side effects conservatively after a release was issued.

Do not assume POLLHUP means all data has been consumed or PIPE_BUF gives socket message boundaries. Read until EAGAIN/EOF subject to a fixed byte budget, with unexpected/excess command bytes terminal. No need to half-close unused directions initially. If using shutdown, distinguish SHUT_RD/WR/RDWR and ENOTSOCK; never shut down both directions of the status channel before flushing its bounded final record. Installed SDK usr/share/man/man2/shutdown.2:49–90 is explicit about separate halves.

Exact intended inheritance (logical descriptors; S's gate endpoint numbers are internal):

| Role/stage | Allowed descriptors and owner actions |
|---|---|
| B | B-side stdin writer, stdout/stderr readers, FD3 peer control sender, FD4 peer status reader; no other process inherits B's control peer. Install readers/error handlers before possible readiness. |
| S before C spawn | 0/1/2 are command-facing ends of B-created stdio streams; 3 control receive; 4 trusted status send; own gate release writer and gate readiness reader; kqueue if used; temporary staging descriptors. No reads/writes on command 0/1/2. |
| sandbox-exec then C gate | Exactly 0 stdin,1 stdout,2 stderr,5 gate release reader,6 gate ready/error writer; exclude S 3/4, kqueue, opposite gate ends and all high temporary duplicates. |
| S after spawn | Close every 0/1/2 copy and staging copy, plus C-side gate ends; retain 3/4, S gate ends, optional kqueue and ownership state. A later allocation can reuse fd0–2, so prohibit accidental printf/perror or descriptor-number assumptions. |
| requested command/descendants | Exactly 0/1/2 inherited by the gate's exec. FD5 closed; FD6 closed or atomically CLOEXEC at successful exec. No lifecycle endpoint, gate writer or S status writer reaches payload. |

S should create native gate pipes CLOEXEC using supported pipe+fcntl in its single-threaded initialization (do not assume pipe2 availability on this SDK). Duplicate all C source descriptors to unique F_DUPFD_CLOEXEC descriptors >=8 before building actions. Explicit dup2 actions map those to 0/1/2/5/6; explicit close actions remove source copies after their last use. Or explicitly addinherit_np unchanged 0/1/2 with carefully staged gate mappings. With CLOEXEC_DEFAULT, assuming stdio inherits automatically is incorrect. Never close a source before all aliases use it. Check every action constructor and spawn return; close every staging FD in S on all outcomes. Do not make inherited 0/1/2 nonblocking as an S convenience: status flags can be shared with C through duplicated open-file descriptions. Only lifecycle descriptors should be nonblocking for supervision.

Direct stdio is the recommended simplification. It removes S forwarding queues, throughput scheduling, duplicated truncation policy and browser-output EPIPE handling entirely. A stopped B reader can block the payload in write while S remains able to terminate it. If B closes a reader, ordinary payload SIGPIPE/EPIPE behavior applies. B must continuously drain within its collection byte limits, then bound post-final draining; do not accidentally stop reading when collection reaches its byte cap. Current collectStream (seatbelt-backend.js:494–516) continues draining and truncates storage, but stop() merely destroys the stream. Add per-stream natural-end/error/forced-close facts and conservative truncation when end was not observed. A 250 ms forced close may have side effects on escaped output holders; it is not proof they terminated. S must put no diagnostic text into inherited stdout/stderr at any stage. sandbox-exec's own errors remain bounded command diagnostic output, never protocol input.

* sys/spawn.h does not attach a historical availability annotation to the SETSID macro, and installed setflags manpage omits SETSID. Upstream libuv explicitly gates it at Darwin19/macOS Catalina in uv__spawn_init_can_use_setsid. Therefore choose >=10.15 as a candidate lower bound for this API combination, not a newly verified backwards-compatibility claim. Arm64 hardware has a higher OS floor. For this product, align the helper with inspected Electron's macOS12.0 minimum (and any higher actual release floor), use explicit deployment targets for both -arch arm64 and -arch x86_64, and inspect Mach-O minOS metadata before adoption. * usr/include/sys/wait.h:162–174 provides WEXITED/WNOHANG/WNOWAIT, :249 waitid; usr/include/sys/signal.h:303 describes SA_NOCLDWAIT. Prior retained-root probe demonstrated WNOWAIT on this host only. Prefer finite WNOWAIT polling as the minimal startup-safe fallback; NOTE_EXIT is a wakeup, not a substitute for establishing wait ownership.
* usr/include/sys/fcntl.h:351,355 provides F_DUPFD_CLOEXEC and FD_CLOEXEC. Gate FDs5/6 must remain non-CLOEXEC through sandbox-exec's first exec into the helper; only then close them or set6 CLOEXEC for requested exec. Setting them CLOEXEC too early breaks the handshake. The installed sandbox-exec man1 page only says it applies a profile and executes the command; it does not guarantee arbitrary descriptor preservation. This double-exec FD preservation is a required targeted proof, not established by my no-exec prototype.

Restore S's empty mask and SIGCHLD default with no SA_NOCLDWAIT before spawn. Keep S SIGPIPE suppressed and all status writes bounded/nonblocking; worker spawn uses SETSIGMASK/SETSIGDEF, and the post-sandbox helper again restores ordinary dispositions/mask immediately before payload exec. Do not inherit a probe safety alarm into production commands. Check syscall failures. S must never depend on B draining either status or output to perform TERM/KILL; allow only a fixed status buffer and finite partial-write retry deadline. EPIPE/status failure triggers cleanup before retirement; after cleanup an undeliverable final is simply missing evidence to B.

execvp preserves argv boundaries but includes PATH search and an ENOEXEC shell fallback (installed usr/share/man/man3/exec.3:161–213). That is compatible with common shell invocation behavior but is not an absolute-path-only/no-implicit-shell contract. Keep explicit argv including the user's command as argv[0], stop helper option parsing at --, and explicitly choose/document this behavior. If strict exec-only semantics are desired, use a deliberate PATH search plus execve without ENOEXEC shell fallback, understanding that this changes compatibility. No shell-string serialization is necessary. Working directory can be B's validated hostWorkingDirectory passed to S and inherited by C (simplest), or a checked addchdir action; never let an untrusted path select the helper/runtime itself.

For reliable exec error reporting, prefer FD6 CLOEXEC after gate readiness, close5 on release, attempt exec, and on failure send a tiny fixed stage/errno record then exit. Bound all gate reads/writes. FD6 EOF alone does not prove exec success: death before exec also closes it. If the simpler close5/6-before-exec option is selected, accept that an exit127 is just actual root status and does not disambiguate exec failure. No untrusted code may retain6, including via the ENOEXEC shell fallback.

Seatbelt and runtime resolution boundaries

The fixed post-Seatbelt helper is reasonable only if its file and replacement-controlling ancestors are outside every payload-writable root. A non-writable file inside a writable directory can be replaced. Reject canonical overlap with the workspace/private storage and prevent a symlink from resolving into them; do not search PATH or permit an environment override. This may deliberately make development fail when the sandboxed workspace includes Freedom's own helper build tree; do not silently copy the trusted helper into the writable execution directory to make that case work. Define a trusted development artifact placement or report unavailable. Canonical-path validation alone is not adversarial same-user atomic code verification; signed bundle integrity and the scoped writable-root threat model remain relevant.

Keep validation/issuance in main workspace-execution, adjacent to SeatbeltExecutor and existing executable/runtime attestation, not renderer policy knobs or a general runtimeRoots entry. Existing electron-runtime.js issues trusted runtime descriptors; it should not be replaced by native-helper discovery or have all its runtime authority inferred from the helper. A separate small native-helper resolver can return a private immutable descriptor from fixed development output or canonical packaged resourcesPath; it checks regular/executable file, expected architecture/build/protocol, supported OS, path protection and policy overlap before S launch. Build/runtime version skew and missing/wrongarch helper fail closed, with no fallback to old JS numeric signaling. A protocol version returned by untrusted code cannot itself attest file integrity: path/build validation must happen first. If the same executable implements S and --gate, gate argv does not grant extra authority; invoking it again from a payload remains under inherited Seatbelt.

Current seatbelt-backend.js:314–317 permits signal/process-info only target same-sandbox; S sits outside that sandbox. Preserve this rule; do not add parent-signal permission or relax networking for lifecycle pipes. C->S signal denial is a policy expectation requiring actual composed-profile proof, not established by UNIX same-UID behavior. Descriptor exclusion comes from spawn/gate closure, not file-read ACLs. Add only exact canonical helper file read/exec rules through a trusted parameter to profile generation. Do not grant its entire bundle/parent as a runtime root. Account for dyld/libSystem reads under restricted exposeSystemToolchain policies without broadening them accidentally. The existing private execution directory is writable (backend:353–355), so profile storage/helper storage must stay conceptually separate; never place helper code there. The static profile is applied before the gate, so gate readiness cannot repair or revoke permissions later.

The environment must be sanitized in B before S's dynamic loader runs. S scrubbing DYLD after entry is useful defense for its child, but too late to protect S from loader injection. execution-policy.js:33–74,136–179 already blocks DYLD_/LD_ and named runtime injection variables; seatbelt-backend.js:666–684 builds an explicit environment rather than spreading process.env. Retain this, with a narrow trusted native envelope if needed, and check bounds/NUL/duplicate keys for any native serialization. Do not eliminate PATH/cwd/runtime environment needed by the requested payload while simplifying S's envelope.

Minimal state transitions

| State | Allowed transition and required action |
|---|---|
| VALIDATING / NO_ROOT | Install B control monitoring, status buffer and absolute startup cap before spawn. A/EOF/error=>FINAL no root; invalid spawn args/flags=>FINAL no root. Successful spawn immediately records direct C ownership. |
| GATED_SETUP | Observe root without reaping, establish gate version/identity and distinct group. Failure/timeout/A/EOF=>ABORTING with only direct C authority until group verified. Root exit before ready=>cleanup/final initialization outcome, no G. |
| READY_WAIT_G | Emit one READY only after every mandatory setup step succeeds. G accepted once if no terminal condition; A/EOF/errors/deadline terminal. Recheck pending commands/expiry before release. |
| RUNNING | Native wall deadline fixed from the chosen start epoch; root waitable=>final original-group KILL path. A/EOF/status/control error=>TERM immediately then KILL at<=1s grace. No release/abort can extend deadlines. |
| CLEANING | Keep C unreaped; final original-group KILL (or direct C if never verified), record rc/errno, settle<=250ms. Permanently disable all signaling, then bounded reap if possible. Missing ownership/waitability=>explicit uncertainty. |
| FINAL / RETIRED | Send at most one bounded FINAL, close status after bounded flush, exit. No signaling even if new input arrives; no PID persisted for recovery. B validates FD4 termination and bounds output drain before exposing completed collection. |

Define the wall-limit epoch explicitly. Minimal conservative choice: S entry starts the approved total execution clock, startup deadline=min(entry+5s, total deadline), never resetting the total on ready/release. If product intends up to30min of payload time excluding startup, document and bound the extra startup budget instead. Native receive/parse loops must have finite work per iteration and monotonic deadlines. TERM grace and KILL settle are scheduling targets, not guarantees under S suspension, kernel stalls or machine sleep; define whether elapsed wall limits include sleep. Natural root exit should final-KILL promptly without an unnecessary TERM grace. B startup/final receipt budgets must cover native startup/TERM/settle plus separately bounded FD4 and stdout/stderr drainage; they cannot terminate S to force the budget.
