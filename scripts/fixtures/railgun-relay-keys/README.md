# Offline relay key-admission campaign

This separate Node qualification campaign reuses the reviewed [relay-wire build](../railgun-relay-wire/README.md). It adds no preparation graph, dependencies, network requests, profiles, full-wallet initialization or production relay authority. It does not change the wire recipe's eleven pins or its default 39-case campaign. No application module imports this fixture.

Use a locally reviewed wire build and its independently obtained manifest digest:

```sh
node scripts/qualify-railgun-relay-keys.js check --build /absolute/reviewed-build --build-sha256 REVIEWED_MANIFEST_SHA256
node scripts/qualify-railgun-relay-keys.js run --build /absolute/reviewed-build --build-sha256 REVIEWED_MANIFEST_SHA256 --output /absolute/fresh-key-run
```

Only locations and the trusted build digest are configurable. The existing wire verifier checks its recipe, selected upstream source, dependency graph, tools, source configuration and generated bytes before importing `upstream.cjs`. This campaign additionally binds the exact Noble 1.7.5 source pin and checks the required API shape on `upstream.ed`. It uses that verified bundled namespace rather than another dependency import. Build and five key-recipe execution-file pins are rechecked after the campaign; only then is `report.json` written. Output must be fresh and outside the build, configured input roots and key fixture directory. A failed run can leave diagnostic output, but cannot overwrite a previous report. The CLI is a local execution guard, not a sandbox or an approval system; a digest delivered with an untrusted rewritten build is not independent authority.

The strict CommonJS port preserves the previously reviewed admission declarations and all seventeen original campaign bodies. Completion requires three positive cases, six negative cases, six controls and two explicit limitations, with ten signature calls, six direct ECDH calls and four wallet-encryption calls. These counters describe this fixture, not all internal cryptographic operations. Random ephemeral keys and IVs remain fresh. A new execution produces its own report and is not implied by source equivalence or unit-test success.

The public-key gate requires canonical compressed encoding, a nonidentity point, and prime-subgroup membership. Signature R receives a separate hardened point check, and S must be below the group order. This deliberately rejects the campaign's mathematically valid identity-R signature, which raw Node and Noble accept. That is an explicit compatibility restriction, not evidence of a forgery. Three genuine synthetic keys demonstrate admission beyond the earlier two-key allowlist. Caller buffers and retained token bytes are detached, including at actual signature, ECDH and wallet-helper await boundaries.

The invalid-peer ECDH cases prove refusal before helper counters advance; their bare rejection assertions do not independently identify the exact rejecting guard. No explicit off-curve adversarial vector is qualified. Noble supplies the point arithmetic and ECDH on both sides; Node provides a distinct Ed25519 signature implementation, while AES comparisons share the Node backend. Mathematical validity and message authentication do not identify a broadcaster operator, bind a Waku peer or external chain topic, authorize a transaction, establish finality, or activate production transport.

The original case definitions remain byte-exact; vector JSON receives formatting only, with identical values. Their source-definition status text is retained. `recipe.test.js` exercises CLI parsing, real verifier digest refusals and explicitly mocked preimport ordering seams using marker-only bundles. It performs no actual upstream cryptographic campaign. The original wire tests continue to cover their verifier separately.

```sh
npm test -- -- --runInBand scripts/fixtures/railgun-relay-keys/recipe.test.js
npm run lint -- --max-warnings 0
```

The existing wire `licenses.json` records selected upstream license sources. This fixture distributes local policy and qualification code, not Noble or other upstream implementations. Generated bundles need their applicable original license and notice material before redistribution.
