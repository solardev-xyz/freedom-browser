# Interrupted PPv2 scan recovery

A failed SDK discovery pass previously lost all completed event-download work before its final note/cursor commit. The host now retains complete, bounded public-event pages in a separate encrypted cache. A retry or reopened profile can reuse a page after rechecking its canonical end-block hash. The SDK still owns note discovery, decryption and cursor persistence; these checkpoints do not advance its cursor or establish spend authority.

Pages are exact matches for the effective provider query: granted contract, sorted event topics and inclusive range after deployment-floor clamping. The cache binding includes chain, identity/account, SDK/adapter pins, deployment and provider grants. A page is saved only at or below an observed finalized block, with matching end-block anchors before and after download. Logs at the end block must match its anchor, and logs sharing a block number must agree on the block hash. Reuse applies the current provider validator again and returns a fresh copy. Both live and reused pages consume the same scan budget and report progress.

RPC state remains unverified, and an anchor cannot prove that an RPC supplied every log. A lagging log index can omit events despite returning a finalized block. Entries therefore expire after one hour; future timestamps are expired too. The main-only `bypassScanCache` option forces a live refresh and may replace the page. Fresh `inspectNoteRecovery()` uses a separate provider with no cache at all, preserving its role as independent reconstruction evidence. Expiry cannot itself rewind a cursor the SDK already committed after an incomplete response; a fresh recovery inspection remains necessary to investigate missing history.

The cache uses a different storage subject (`operation: scan-cache-v1`), HMAC domain and encrypted file from SDK notes, inside the existing profile store directory. Its capacity is 256 pages / 512 KiB, with oldest-page eviction and no caching of an oversized page. Atomic updates serialize concurrent windows. SDK storage retains its independent quota. Every saved page is currently persisted; batching would trade away recovery of the most recent pages and awaits performance measurements.

A malformed cache payload or changed binding is treated as empty and replaced in place. An unauthenticated cache file is preserved, caching is disabled for the session, and a sanitized diagnostic is emitted. Cache-only finality/anchor failures cause live reads without reuse or writes. Cache write failures cannot turn valid downloaded logs into a failed sync. Actual contradictory anchors/logs, revoked lifetimes and inventory failures still stop the operation. Once listed in the authenticated inventory, **never delete the cache file**: a missing file blocks PPv2 and enrolled Sepolia sends. Resetting its contents in place preserves the inventory.

Each provider has its own monotonic progress reporter. Accepted increments contribute to session-wide totals, so a fresh uncached recovery provider can renew the stall timeout immediately. Duplicate or decreasing reports cannot keep a stalled operation alive. Diagnostics count session-cumulative windows, including recovery scans. A fake-timer regression covers a healthy 20-minute recovery after an earlier 100-window scan, followed by stalled duplicate reports.

The added anchor requests have a cost. Finality observations are coalesced and reused for at most a minute when they already cover the requested window. A cache hit normally replaces one log request with one block-header request, plus amortized finality observation; a miss adds two anchor reads. This reduces repeated log downloads, not necessarily Tor latency. No live performance improvement is claimed.

This continuation also requires a classified private transaction intent before signing and at raw handoff, preventing new unclassified private records from permanently blocking recovery. Qualification status and public-resolution outputs omit ordinary transaction target/selector metadata. Existing unclassified records are preserved and still require recovery.

The real-SDK lifecycle fixture now interrupts a cold scan after two completed RPC windows, closes and unlocks the profile, reopens it, and checks that both pages are reused. Its recovered notes match a completely uncached inspection. Unit regressions cover expiry/bypass, reorgs, inconsistent logs, failed anchors, quotas, binding changes, corruption, cancellation and provider budgets. Full unit regression passed 6,848 tests with 33 skips; six OpenLV tests passed separately. The full SDK run passed 18 cases and failed only the deposit fixture's exact RPC-method expectation, which omitted the new header reads. After that expectation was corrected, the deposit case passed separately: all 19 cases have passing results across the two runs. Lint, changed-file formatting and diff checks passed. The runtime pin is unchanged; no live transaction or funded-profile modification occurred.
