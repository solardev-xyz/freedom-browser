# Public Shield facade: cold resolution and normal note credit

Reviewed implementation plan, October 5, 2026. Implementation and native qualification of this complete three-process path remain pending. The [source inventory](https://github.com/solardev-xyz/railgun-kohaku-adapter/blob/377c2a5d1aca18f0ed328dfdda955bd7d1ba271c/docs/freedom-qualification/railgun-public-facade-cold-credit-plan-sources-2026-10-05.json) binds the inspected checkpoint at `868f43a3`; line references below refer to that snapshot. The later Kohaku contract campaign changes fixture instrumentation, not the production interfaces described here. This plan incorporates independent source review and seven corrections covering chain continuity, event position, owner binding, recovery drainage and transport boundaries.

## Concrete missing connection

The public facade already hands its genuine wallet phase to the Shield controller and returns a one-use public operation (`railgun-kohaku-plugin.js:694–983`; `railgun-kohaku-public-submitter.js:1–15`). Its offline fixture verifies genuine preparation/receiver/preflight, vault EOA signature, journal-before-send, acknowledgement loss, copied/replayed tokens and drainage, but explicitly reports `coldResolutionOrNoteIngestionQualified:false` (`scripts/fixtures/railgun-kohaku-public-integration.js:689–780`).

The direct-controller qualifier separately resolves matching synthetic receipts after vault lock/unlock (`qualify-railgun-shield-submission.js:579–689`). This is same-process reopening, not a fresh Electron process. It constructs the Shield log from the actual signed multicall (`:416–474`), but does not run subsequent wallet ingestion. Historical documentation also includes live preflight activity; do not run that entry point unchanged or import its live helper for this new slice.

The smallest complete addition is a **new offline three-process qualifier**, acknowledged and accepted-but-response-lost variants: six fresh disposable processes total. Preserve the existing public fixture CLI/defaults and its three modes. No production API addition is indicated by this source review. No generic Kohaku host, extraction, renderer activation, private withdrawal, POI acceptance or spendability claim belongs here.

## P0 — actual public facade deposit, then shutdown

1. Create the normal disposable public-vector vault/enrollment/public generation and completed wallet baseline. Use the real enrolled EOA signer derivation with synthetic balance responses, not a substituted signer. Fixture-written public wallet metadata must be labeled as such, not production onboarding evidence.
2. Install transport interception before privacy RPC/service imports in **every process**, including P1/P2 before their cold openers. Assert those modules are uncached at installation; do not assume P0 interception crosses a process boundary. Reuse the offline pinned-bytecode deployment helper, genuine RPC clients/destination constraints and actual facade/controller. Reject unknown methods/contexts/endpoints; no outbound socket fallback. Keep protocol-source and public EOA traffic separate.
3. Construct the public plugin with the genuine account/owners and explicit reviews; call `prepareShield({asset:{__type:'native'},amount}, instanceId)` then the public submitter. No prover archive/artifacts/private-proof configuration. Retain existing first-review denial and wrong/copied/private-broadcaster token controls where reuse is practical; baseline these separately from the successful operation.
4. In the intercepted **actual** raw send, parse and compare the signed intent and assert the actual encrypted journal already holds that hash/nonce/intent in `attempted`. Exactly one EOA signature and one raw-send entry. Ack returns the same hash; loss is injected only after acceptance and returns genuine `PRIVATE_BROADCAST_UNCERTAIN`, with no retry.
5. Decode the actual shield call to generate the synthetic canonical receipt/source event: same NPK, token and every encrypted ciphertext word; value equals journal noteValue and fees is exactly `[gross - net]`. Derive tree/startPosition from **all leaves in the actual baseline public generation**, including Shield and Transact commitments, not owned-note count or EOA nonce. Require startPosition <65536, one new leaf and a unique canonical logIndex. Preserve prior logs and commitments byte-for-byte. The direct qualifier's nonce-as-position shortcut is unsuitable for this nonempty wallet.
6. Put the Shield in a **new block strictly after the baseline checkpoint.to.number**. The first appended header has parentHash equal to baseline checkpoint.to.hash; every later header links to its predecessor. Choose explicit scan `to` and `anchor` with Shield.blockNumber <= to <= anchor.number, at least three reported confirmations, and finalized height at or beyond Shield inclusion. Persist the complete deterministic header table (numbers, hashes, parent hashes and latest/finalized references), hash-bind it in the handoff and reuse identical entries in P1/P2. The same table serves public scan and EOA recovery; neither process regenerates inconsistent anchors.
7. Save only a strict hash-bound test handoff and synthetic public-chain wire fixture outside the account directory: source/runtime hashes, process/run identity, public submitter/transaction identity, baseline checkpoint/inventory hashes and expected public event coordinates/values. No raw signed transaction, key, opaque token, private note snapshot or authority serialization. Persist only plain RPC transaction fields required by the matcher (hash, nonce, chainId, from, to, value, input and inclusion block fields), receipt/logs and the header table: **no v/r/s or serialized signed transaction**. Assert that closed wire schema. Public transaction input/ciphertext needed by the offline service is fixture wire, excluded from published reports and clearly labeled public-vector synthetic chain data.
8. Close/drain plugin, wallet owners, enrollment, identity, vault and profile. Launcher waits for actual Electron PID exit before P1; record clean restart, not power-loss recovery.

## P1 — cold journal recovery, then explicit normal scan

1. Unlock the existing vault, reopen genuine enrollment/public generation with `create:false`; do not import/repair/rebuild. Use genuine vault wallet metadata (or a counted genuine signer address lookup) to locate the owner-bound journal, then authenticate its singleton Shield attempt and owner binding. Cross-check the authenticated journal context principal against that independently obtained vault owner; pass that owner to recovery, **never an owner authorized solely by the handoff**. The Shield intent stores a sender-bound digest, not an `intent.from` field: require the RPC transaction.from to equal the authenticated owner and recompute its exact intent digest during matching. Compare hash/intent/nonce to the handoff only as fixture consistency checks. Recreate fresh reviewed destination context/constraint, never reuse P0's token. Bootstrap credential/worker activity is measured separately.
2. `openRailgunShieldRecovery(owner,{signal,destinationConstraint})` creates an independent public-address transaction context (`railgun-shield-recovery.js:25–75`). Use its genuine `list`, `observe`, and `resolve(hash,{minimumConfirmations:3,review})` (`:147–279`). Return the explicit existing `{allowNextTransaction:true,acceptedEvidence:'unverified-rpc'}` review decision only after verifying the exact summary.
3. Match the real persisted transaction against synthetic receipt and canonical/finalized headers. The matcher compares RPC transaction fields to the journaled intent and hash, and binds proxy log, NPK, token, ciphertext and value+fee (`railgun-shield-receipt.js:1–132`). Assert the resulting durable resolution contains that precise note and preserves the original intent. It does **not** reconstruct a signed transaction or cryptographically recompute its transaction hash from signature components; require a unit/fixture control exercising this exact plain-RPC schema and do not claim signature verification during recovery. P0 independently checks the real signed transaction. Receipt/finality remain unverified RPC evidence.
4. Resolve **before** wallet advance. Assert resolution alone has not changed wallet SQLite, coverage or wallet checkpoint/notes. Cold opener lifecycle/catalog writes must be accounted for separately, not falsely described as zero storage changes. Recovery phase must perform no EOA signing, raw send, Shield preparation/receiver, private intent/B/prover/C or POI/TXID service acquisition.
5. Close the recovery owner, await its admitted callback/closed barrier, and assert its transaction-RPC handle has reached transport release before starting scan-phase baselines (shared transport lifetime is separate; no physical socket-drain claim). Then explicitly advance the genuine public owner across the new Shield block using **`publicAccount.advance({to,anchor})`** (`railgun-account-public.js:262–269`), then call ordinary `openRailgunAccountWallet({...owners,archive,mode:'advance'})`. This runs real engine scan, coverage write, wallet journal completion and current read issuance (`railgun-account-wallet.js:476–532`). No injected typed note or fake scan receipt.
6. Read genuine owned records and public facade/read balances. Exactly one newly received unspent Shield matches transaction hash, tree/position, WETH/sub-ID, net amount, event NPK and actual engine commitment. `railgun-wallet-records.js:15–63` decrypts the original payload and recomputes NPK/hash; use this genuine path rather than making a second fixture-selected ownership claim. Assert exact WETH balance delta +net, all baseline notes/spent statuses unchanged, tree length +1 and canonical prefix preserved. Do not assume the wallet previously had one or zero notes.
7. `railgun-kohaku-read.js:37–83` deliberately tags balances `unverified`, reports `poi:'unverified'` and `spendableGranted:false`; preserve those exact results. Shield credit needs public scan and actual viewing work, not a TXID mirror or POI list service. Close/drain all resources before P2.

## P2 — retained credit and resolution, without advancing again

Authenticate the durable resolved Shield and completed public/wallet checkpoint; obtain the same owned note and exact net balance once. No public advance, new Shield, signer, send, private proof or POI/TXID request. A repeated read/restore cannot credit twice. Compare persisted note/checkpoint semantics and documented constructor lease/floor changes separately from actual credit writes. Completed restore can read source headers/logs: do not demand zero RPC or use a writable fallback if it refuses.

## Distinguishing negatives and measurement

- Before healthy resolution, synthetic receipt unavailable: genuine unknown/unresolved outcome, no resolution and no wallet advance/credit; no resend. Then make the same accepted transaction visible. Label this lagging synthetic RPC, not proof of absence.
- Wrong ciphertext/NPK/value sum, removed or wrong-anchor receipt, insufficient depth/finality, and denied resolution review must refuse resolution. Observation/revision updates can be legitimate; compare immutable intent and unresolved status, not blind whole-journal byte equality. Prefer existing receipt/recovery unit controls plus one native ciphertext/anchor control to avoid redundant process campaigns.
- Do not claim unresolved receipt prohibits the ordinary scanner from independently finding a genuine received note. In this harness the chain fixture is deliberately coherent and explicit advancement is withheld until the healthy path. Receipt resolution and owned scan evidence are separate authorities.
- Source replay/restoration must preserve exactly one credit and unrelated notes. A fixture mutation control should make the new event's payload foreign/corrupt and demonstrate that the genuine scanner does not grant the expected owned credit; distinguish intended classification from unexpected process failure.
- First-statement counters and sticky observer failures must cover signer/address reads, transport entries, child starts/exits, viewing-key loans/wipes and late callbacks. Native assertions inside callbacks must survive sanitized refusals. Closed/aborted contexts, exact wire shapes and bounded pending counts remain enforced at the intercepted transport.
- Expected semantic counts are fixed now (one EOA sign/send, one new Shield/credit, zero proof/POI/TXID work). Exact bootstrap utility/worker/key and recovery header-query counts must be derived from the chosen actual entry points before freezing the harness; do not invent totals or assert all credential activity is zero. Shared transport create/release counters and legitimate journal observation transitions need explicit phase baselines. The first actual request lazily allocates the module-level shared transport: attribute that creation to the process/phase where it occurs, rather than expecting a transport per preview handle. Assert recovery-handle release before public advancement; later shared-transport close is not that release.
- Required compatibility: existing public acknowledged/lost/review-cancelled fixture modes, read-only wallet restoration, and unchanged direct-controller offline resolution route. Run relevant receipt/recovery/facade tests and lint; record true process exits and source hashes for every native report. Do not republish synthetic wire/profile files.

## Acceptance and limits

Success means: the genuine public facade's one journaled signed deposit survives a real clean process restart; the independent controller explicitly resolves its matching receipt; the ordinary scanner decrypts and credits precisely its net WETH; a further cold completed restore retains the same single credit. Both ack/lost paths must demonstrate this with actual crypto, encrypted persistence, phases, worker drainage and destination guards, while all remote chain/service answers remain synthetic. It does not establish live mining, consensus finality, Tor isolation, list acceptance, spending eligibility, browser UI, or a portable Kohaku backend.
