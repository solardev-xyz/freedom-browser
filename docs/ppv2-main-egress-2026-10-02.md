# PPv2 main-process egress checks

Both controlled native and token full-value lifecycles pass with **zero direct egress attempts observed across eight fresh Electron instances**. Each instance first exercises all **92 installed hooks** as positive refusal canaries (each installed hook invoked directly), recorded separately from the actual operation. The fixture then loads the authenticated SDK and runs registration/deposit, withdrawal, checkpoint recovery or second spend/zero-note refusal, depending on the stage. No canary reset can erase operation attempts.

The hooks cover main-process JavaScript fetch/WebSocket, HTTP(S), sockets/TLS/HTTP2, UDP, DNS including resolver prototypes, Electron net, Session fetch/host/proxy resolution, Worker creation and child-process entrypoints. Socket prototype interception also catches Node connections made through earlier captured helpers. Hooks are installed before the runtime is loaded in each process. Calls are counted before refusal, so swallowed errors still fail the zero-attempt assertion. Unit controls exercise rejection and exact descriptor/prototype restoration.

The harness waits for chrome readiness, then navigates its own windows to `about:blank` before installation. Initial instrumentation caught Ant API background polling; recorded stacks pointed to the chrome IPC path. Waiting for chrome readiness before blanking the windows removed this unrelated activity without any URL, transport or IPC exemption. This measures a main-only controlled protocol lifecycle, not the browser’s normal background network behavior. Approved host transport is mocked by the existing fixture.

After the protocol session closes, two event-loop turns precede the final zero-attempt assertion. Hooks then remain installed through process shutdown; there is no restored network window. Counts in the report stop at the pre-shutdown assertion, so shutdown refusals are not reported as measured zeros. Denial can change graceful app shutdown in this harness. This does not establish the absence of indefinitely delayed timers.

Coverage is intentionally bounded: code loaded before installation may retain references to Electron/worker/process APIs; native addons, Chromium navigation and renderer traffic are not covered. Existing utility-process denial hooks remain separate evidence. These JavaScript hooks are not a security sandbox against malicious native code or deliberate runtime mutation, and this is not exhaustive application/SDK egress qualification.

The final canary-bearing run passed both real-SDK cases with no skips or retries in about two minutes. Only the two full-value cases opt into this instrumentation; other cases retain their original evaluation path. The full 21-case SDK suite had passed before this test-only instrumentation; do not describe the entire 21-case suite as egress-instrumented. A separate non-instrumented controller regression also passed after adding the explicit delegation for other cases. Claude reviewed the instrumentation and bounded evidence. Two focused tripwire unit cases, lint and branch-changed-file formatting pass. The earlier readiness run was interrupted after the native case passed to incorporate the final shutdown/canary checks; it is not the final evidence.

[Machine-readable evidence](qualification/ppv2-main-egress-2026-10-02.json) contains the common hook inventory, each instance’s refused-canary counts and empty operation-attempt list, and source hashes. No live transaction was submitted, application network policy was not changed, and no funded profile was accessed.
