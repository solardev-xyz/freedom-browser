# Railgun persisted frontier inspection — October 2, 2026

Main can now inspect the authenticated engine database without trusting a child-supplied progress message. It distinguishes missing state, incomplete state and structurally plausible persisted state, rejects candidate positions outside the published tree length, and invalidates observations after any write or transaction begins. **No result establishes scan completeness, a balance, ownership or permission to spend.** Even the most permissive result is `persisted-unverified`, with `rootBinding: 'unverified'` on the frontier.

This follows the [atomic tree-write qualification](railgun-tree-transactions-2026-10-02.md). It adds development infrastructure under `src/main/wallet/`, consistent with main's existing ownership of protocol state and persistence. The engine child cannot request these inspection methods through its command protocol; no renderer API, IPC channel or enabled product adapter is added.

## Pinned interpretation

`railgun-frontier.js` reads UTXO V2/Sepolia records from the engine 9.6.0 layout. The [golden vectors](qualification/railgun-frontier-vectors-2026-10-02.json) were captured from the authenticated installed fixture, inventory SHA-256 `d46dbb16c9161c25baffe12701b2efdb844cb788f7e083d610729973d009e420`. The actual-engine reproducer compares all six captured paths and four MessagePack encodings against upstream functions on every child run.

The UTXO metadata key consists of padded hex UTF-8 `merkletree-erc20`, network `aa36a7` and hex UTF-8 `V2`. Node paths append tree, level and index; commitment data uses level marker `ffffffff`. The history/cursor namespace instead pads literal lowercased ASCII: `chain_sync_info`, the upstream spelling **`merkleetree_history_version`**, and `last_synced_block` / `v2_poseidonmerkle`. Confusing those two encodings silently misses records, so the paths are explicit qualification evidence.

Main requires history version 13 and a canonical unsigned decimal synced-block value. That value is an engine claim, not a chain anchor. The bounded MessagePack parser accepts only the metadata schema's maps, printable strings, unsigned safe integers and nil: at most 64 KiB, 256 entries per map, 4,096 decoded items and depth six. It rejects duplicate/prototype keys, unsupported types, truncation, trailing bytes and out-of-range values. Metadata identifies trees and their `scannedHeight` (leaf count, at most 65,536), plus optional invalid-root details. Prior trees may be partially filled when an insertion batch rotates to a new tree. Roots and inspected leaves must be 32-byte BN254 field elements.

Missing/unsupported history, missing cursor or metadata, gaps between tree indices, missing roots and invalid-root reports leave the frontier incomplete. Main also probes these boundaries:

- A nonempty listed tree must have both its last published leaf and commitment record.
- If that tree has room, neither record may exist at the first unpublished index.
- Neither first leaf nor first commitment may exist in the next unlisted tree.
- Missing metadata accompanied by the tree-zero root or first commitment is incomplete rather than unscanned.

These are bounded point checks, not exhaustive enumeration. `unscanned` means the inspected metadata/cursor/history and orphan probes were absent; it does not prove the entire database empty. Boundary existence does not validate every commitment or bind the stored root to the reported length. An interior inconsistency or a gap farther beyond the checked boundary can still evade this structural inspection. Independent Merkle recomputation and chain evidence remain necessary.

The TXID tree (`railgun-transaction-ids`), wallet records, nullifier history and POI are outside this reader's scope. Upstream `updateInvalidMerklerootDetails` writes outside `writeTreeToDB`; ordinary session writes still invalidate observations. History/cursor/reset writes are also separate from an atomic tree group.

## Lifetime and candidate positions

`inspectFrontier()` reads synchronously from one main-owned store revision and refuses while a write group is open. A session-private WeakMap binds each issued frontier to its revision. Writes, namespace clears and transaction begin invalidate earlier observations, including when that transaction later aborts. Closure, lock or profile-generation changes revoke the session. The session exclusively owns the store; any future write path must advance the revision or move revision ownership into the store.

`inspectPosition(frontier, { tree, index })` requires a fresh issued frontier with status `persisted-unverified`, an index below its published length, a stored leaf and a bounded JSON commitment whose normalized hash equals that leaf. Ineligible requests return `RAILGUN_FRONTIER_NOT_ELIGIBLE` without closing the session. Missing or malformed in-range records, hash mismatches and malformed frontier records revoke the session. Position and freshness checks reject clones, serialized observations and observations from a reopened session.

Both frontier and position observations are registered for `assertFresh(observation)`. A future consumer must call this immediately before use, without an intervening await; any later asynchronous operation needs its own revalidation. Freshness only binds the observation to local state. It does not upgrade its trust, verify membership under the stored root, or authorize proof generation/signing.
