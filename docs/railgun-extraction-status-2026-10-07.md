## Freedom host obligations

- The raw `/host/data` and `/host/poi` entries accept trusted, normalized host inputs; public `/data` separately validates unknown inputs. They do not grant ownership, consent, signing or submission authority; raw exceptions must not reach renderer/user output. The three POI selector integration tests remain host acceptance tests.
- Until the owner move is installed and qualified, Freedom still owns identity/enrollment, selectors, process and storage supervision, controllers, genuine owner registries, Tor/RPC destinations, and EOA journal/submission. Moving data or job implementations does not move those authorities by implication.
- Host contexts, profile/vault sessions and encrypted I/O remain genuine host objects. Package owners must share one instance for receipt/permit registries, preserve original child/callback drainage, and keep uncertain work reserved. No caller-selected module resolver, verifier, signer or raw-key facade is allowed.
- The fixed credential host temporarily retains derivation: spending `m/44'/1984'/0'/0'/<index>'`; viewing `m/420'/1984'/0'/0'/<index>'`; storage-root HMAC domain `Freedom Railgun account storage v1\0` (the escape denotes one NUL byte) followed by JSON `[profileId,index,11155111,"sepolia"]`. `profileId` is SHA256 of JSON `[profile.id,profile.userDataDir]`. Index is 0–65535. The storage loan creates the genuine profile guard before seed wipe; it never exposes the seed. This retained algorithm must be addressed before claiming complete extraction.
- Credential admission binds the genuine private account, Railgun/Sepolia and purpose: storage-root requires storage / `railgun-account-enrollment-v1`; spending-public requires keystore / `spending-public`; spending-sign requires keystore / `spending-sign` or `relay-sign`; viewing requires keystore / null or `viewing-identity`. The vault session and original context/profile must remain current through callback settlement. Package spending and storage-root callbacks are private and retained until original admitted work drains. Viewing keys are copied to supervised utility children; those host loans end after the copy, and an unknown viewing-child exit does not itself retain the stable-account signer latch.
- Every future qualification inventory must include the installed package closure, lock integrity, relevant host entry and actual runtime/native inputs. Historical reports qualify only their recorded versions. Source hashes are not complete execution traces.
- Synthetic-list relay campaigns use physical single-link copies, verified separate inodes, a single reviewed write-then-rename literal substitution, and original/copy rechecks. They never alter the authentic installed trust policy or establish live-list acceptance.
