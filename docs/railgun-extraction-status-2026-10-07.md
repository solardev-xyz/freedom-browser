## Freedom host obligations

- The raw `/host/data` and `/host/poi` entries accept trusted, normalized host inputs; public `/data` separately validates unknown inputs. They do not grant ownership, consent, signing or submission authority; raw exceptions must not reach renderer/user output.
- Eight Railgun host files remain: the credential, submitter and fixed key-derivation adapters; main owner composition; platform and source-identity adapters; and the utility and storage entry stubs. They bind actual browser vault/session, privacy contexts, encrypted I/O, Tor/RPC, Electron/worker resources and the ordinary EOA journal. Package owners retain the genuine identity/receipt registries and admission rules; a generic process spawn port does not grant signing or submission authority.
- Host contexts, profile/vault sessions and encrypted I/O remain genuine host objects. Package owners must share one instance for receipt/permit registries, preserve original child/callback drainage, and keep uncertain work reserved. No caller-selected module resolver, verifier, signer or raw-key facade is allowed.
- The small [fixed key-derivation adapter](../src/main/identity/railgun-key-derivation.js) remains a host responsibility: the original spending/viewing paths, account index bounds and storage-root HMAC domain stay unchanged. The surrounding credential host supplies the actual vault/session and profile, creates the genuine profile guard before seed wipe, and never exports the seed through its public capability. The derivation helper itself takes an already-admitted seed and hardened path; it does not perform vault admission. “Owner extraction complete” does not mean every Railgun-specific host integration line has disappeared.
- The [credential adapter](../src/main/identity/railgun-credential-host.js) admits only fixed Railgun/Sepolia purposes and actual contexts. Package-private spending and storage-root callbacks preserve original admitted-work drainage and buffer wiping; viewing-key copies go only to supervised utility children. Closing an outward operation is not evidence that its original work has settled.
- Source policy binds the installed package and exact host implementation snapshot at one-shot initialization. Package changes conservatively invalidate derived generations; old authenticated custody is retained, with no automatic pruning. Every qualification inventory must include the installed package closure, lock integrity, host entry and actual runtime/native inputs. Historical reports qualify only their recorded versions; hashes are not execution traces.
- Synthetic-list relay campaigns use physical single-link copies, verified separate inodes, a single reviewed write-then-rename literal substitution, and original/copy rechecks. They never alter the authentic installed trust policy or establish live-list acceptance.
