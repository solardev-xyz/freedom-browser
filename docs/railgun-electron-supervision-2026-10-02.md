The private main-process supervisor now runs the approved engine fixture in an actual Electron utility process. [Recorded evidence](qualification/railgun-electron-runtime-2026-10-02.json) contains source hashes and 13 passing scenarios on Electron 44.4.5 / Node 24.21.0, macOS arm64. Four scenarios initialize engine 9.6.0; nine exercise intentional startup/lifecycle failures. ## Ownership and failure handling

`src/main/wallet/railgun-process.js` owns the process, encrypted storage session and scoped RPC capability. Main is the existing wallet and persistence owner; the engine has neither the database key nor a direct SQLite reference. Keeping this boundary in main avoids granting persistence authority to the renderer or engine. The main-only caller must select an authenticated runtime entry and minimum viewing-only input; arbitrary entry selection is not exposed to users. Runtime distribution authentication and product enrollment remain separate work.

One transferred MessageChannelMain port carries commands, replies, readiness and sanitized failure reasons. ParentPort is initialization-only; subsequent traffic there closes the session. Commands dispatch synchronously on arrival so the broker establishes request ordering before any await. Failure reasons and channel closure share the same ordered port. Readiness requires both successful job initialization and an observed in-limit memory sample; it conveys no scan, balance or proof result.

Limits are two children globally, one per profile generation/account subject, eight active broker requests, 64 KiB initialization input, 2 MiB broker frames, and a bounded outer JSON envelope. Defaults are a 30-second startup deadline, ten-minute lifetime, 256 MiB V8 heap and 768 MiB sampled RSS ceiling. Missing memory observations fail closed. The child queue adds up to 1,024 waiting operations / 8 MiB with a 30-second queue deadline. Admission snapshots arguments; queued cancellation releases them promptly.

Lock, shutdown, invalid traffic, resource limits and storage faults revoke main-owned capabilities before termination. A process retains its owner/global slot until observed exit. A never-spawned process reports a distinct startup failure while retaining capacity until exit can be established. POSIX uses direct SIGTERM and a 250 ms SIGKILL fallback. Electron's own kill implementation additionally schedules Chromium termination, so the POSIX supervisor owns this grace interval explicitly ([pinned Electron implementation](https://raw.githubusercontent.com/electron/electron/v44.4.5/shell/browser/api/electron_api_utility_process.cc)). Windows still uses Electron kill and has not been qualified.

## Actual-process evidence

| Scenario                         | Observed outcome                                                                                                                                                                                                                                                     |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create, lock, restore, app quit  | Four actual-engine children use main-owned encrypted storage, public fixture viewing material and a spending public key. Real engine database reads survive a 128-read burst; fresh restoration preserves the fixture identity. Lock revokes the pending scoped RPC. |
| Stalled initialization           | Startup deadline revokes and terminates the child.                                                                                                                                                                                                                   |
| Crash                            | Exit/disconnect is observed and authority is revoked.                                                                                                                                                                                                                |
| Malformed parent-channel message | Main closes the session; the initialization channel cannot become another RPC path.                                                                                                                                                                                  |
| Memory allocation                | Main records a baseline below the 256 MiB test ceiling before allowing a retained 384 MiB allocation; the next sampled over-limit RSS closes the child. This establishes causality rather than relying on startup memory.                                            |
| Private-channel disconnect       | Main detects peer closure and revokes the session. Local child port closure is not assumed to make the child exit itself.                                                                                                                                            |
| Missing entry                    | The child reports a sanitized job failure through the private channel.                                                                                                                                                                                               |
| Revocation before spawn          | Startup fails with privacy-context revocation and the eventual child exits.                                                                                                                                                                                          |
| Caught direct-egress attempt     | The fixture catches the network exception, but the guard still notifies main and causes `RAILGUN_PROCESS_EGRESS_REFUSED`.                                                                                                                                            |
| Wedged event loop                | A SIGTERM-ignoring, Atomics-blocked child requires SIGKILL. Same-owner admission stays busy until observed exit, then succeeds.                                                                                                                                      |

The checked guard installer replaces and canaries 90 JavaScript hooks in this Electron version, including Electron net request, fetch and resolveHost. An unpatchable required hook refuses startup. All four real-engine checkpoints record 90 canaries and zero engine attempts. `guardReport` is a development/qualification helper, not a product capability. Environment values are blanked before fork and removed before loading the job; child output is discarded. All key material in these runs is public fixture material. No account/profile with funds is touched.

These hooks address accidental bypasses. They are not an OS sandbox: native code, filesystem access and deliberate hook removal are not contained. IPC size checks happen after runtime message allocation. RSS sampling is a soft limit, so an allocation can exceed its ceiling between samples. The memory case measured 64.64 MiB before the allocation and a 449.73 MiB peak against its 256 MiB ceiling. The report records this overshoot; it does not establish a hard memory bound.
