# Railgun operation-window POI — October 3, 2026

Main can now obtain a fresh POI receipt for exactly the input captured by a genuine active private-operation window. It does not reuse a diagnostic read receipt after that view has expired. This is signing infrastructure only: no owned-note query has been sent and no live spending authority is enabled.

`openRailgunPrivateWindowPoi` derives its one note from the window's authenticated owned projection and selection. The module-private shared factory cannot accept caller-injected ownership. Separate opaque registry checks bind operation versus diagnostic paths, exact window token, account, identity, enrollment and coordinator. The window observation carries the internal note ID/hash, tree/position, nullifier, blinded commitment, scan-derived input type and checkpoint. These linkable fields must remain out of logs, reports and the Kohaku read surface.

Only a Valid required-list status, accepted service root and independently verified membership produce a window receipt. Non-Valid statuses or rejected roots return `{status: 'refused', observation}` without a receipt. Diagnostics retain advisory receipts. A transport or verification error closes the operation and rejects; the future controller must translate expected external failure into a normal refusal. Close the POI operation after every outcome. Neither a verified receipt nor its observation grants spending, transaction provenance or consensus trust.

Each window attempt receives a fresh POI operation identifier and Tor isolation scope, separate from diagnostic queries. Tor still exposes the requested blinded selector, selected grouping and timing to the POI service; isolation is not query privacy. Repeated attempts are new disclosures, so retries must remain bounded and deliberate.

Receipt freshness starts before the first status request. A source acquisition has one total budget up to 45 seconds, with each request limited to the remaining time. Callers can shorten it with `acquire({timeoutMs})`; they cannot extend it. Window acquisition also clamps that budget to the window's remaining lifetime and includes the membership process in the same deadline. Its startup/lifetime budget is the remaining time, and abort closes the transport and child scope. The caller waits for the child's observed exit before continuing. As elsewhere, a non-cooperative mocked/custom callback cannot justify releasing account phase before its child drains.

Source, membership and window assertions all propagate the requested remaining-time margin. The source checks `age + margin < 60 seconds`; membership inherits the same start, and the window also checks its own deadline and prover liveness. Clocks cannot roll backward into a fresh receipt. The signing controller should run POI before private preflight, then compute a common commit deadline with room for signing, proving and independent verification. It should refuse insufficient budget before exposing a key. The initial production controller must derive its Shield-only restriction from the authenticated input type; Transact inputs still need creating-TXID provenance and post-transaction POI.

The diagnostic entry copies and freezes its selected IDs before creating the lifetime checks. Mutating the caller's original array cannot skip subsequent note-reference validation.

Validation covers fixed selection during busy account reads, cross-brand and cross-owner rejection, forged receipts/windows, independent circuit subjects, non-qualifying results without receipts, lifetime revocation, stalled transport, membership drain, cumulative request deadlines, shortened/invalid budgets, stale receipts and margins, and the diagnostic list-mutation regression. The three affected suites pass 63 tests; lint is clean. Claude reviewed all six source/test files and approved them. The unchanged-source full regression passes 8,749 tests (33 skipped), across 420 passing suites with the existing `openlv-protocol.test.js` exclusion. All checks used controlled fixtures; this is not a live owned-note POI qualification.

This changes main-owned POI orchestration only. There are no new dependencies, IPC channels, renderer changes, wallet-policy changes or public/TXID cache invalidations. Funded transfer/unshield remain open, and the owned-note disclosure approval remains pending.
