# Local relay custody data

The internal recovery writer and shared reservation codec establish bounded durable formats for the connected local Railgun relay operation. Fenced enrollment now opens both through fixed account-owned storage ports. The stores grant no signing, discard, proof-export or transport capability. They live in the main-process wallet modules alongside existing encrypted persistence; no renderer or package boundary changes.

The recovery writer uses genuine fenced enrollment, exact account/context/directory binding, encrypted storage, a fresh lease, exact compare-and-swap, a monotonic authenticated floor and final readback. Original pending work retains same-path ownership after close. A cold opener can repair a lower authenticated floor only when both the document and floor exist. Newer floors, missing stores/floors, stale leases and postwrite failures refuse; failed writers do not retry or compensate.

Each operation keeps its original canonical unsigned draft, membership history, pre-transaction POI binding and immutable intent digest. Signature and proved-transaction slots are write-once. Local discard preserves those slots and distinguishes never-signed cancellation from potentially signed work. The fixed paired reservation methods now establish exact shared-ledger joins, persist the tombstone first, and release the input conflict only afterward. The fixed controller establishes operation authority before using them. Structural transaction/POI matching does not verify either cryptographic proof.

Explicit qualification limits:

- Ten retained operations per account, for its lifetime in this format; terminal records are not pruned. Every record reserves enough space and transitions to finish. The maximum encoded record is below 96 KiB, and ten records plus the envelope remain below the storage value's 1 MiB bound; the storage layer still enforces its aggregate 4 MiB limit.
- An interrupted first creation that leaves a document without a floor is refused, even for an empty document. The format cannot distinguish that crash from restored ciphertext and missing rollback evidence.
- Authenticated operation failures close the writer, including unknown IDs and illegal transitions. Genuine prewrite busy/capacity/conflict refusals leave the shared reservation owner usable; forged error codes cannot select that exception. Reopening a failed writer must go through the genuine owner. This deliberately conservative internal contract is not the eventual product retention or error-handling policy.

The shared v4 codec retains one `(tree, nullifier)` conflict space across private and relay rows, preserves historical origins and reserves terminal transitions before admitting another hold. It has no storage or receipt authority. Private-kind operations in v4 also require genuine current fenced enrollment. Its defensive v3 parser does not imply that a v3 profile format was shipped.

The pure cross-store matcher checks the exact operation ID, immutable relay origin, selected input, checkpoint, draft, expected signature hash and signing metadata. Its state matrix permits only ledger-first signing markers and record-first retirement. A ledger signing marker paired with a still-held recovery record requires completing the recovery marker before discard; otherwise the store would incorrectly classify potentially signed work as unsigned cancellation. The matcher rejects the opposite write orders, historical/private origins and all mismatched joins. It authenticates neither store and returns no permission. The paired store methods independently authenticate both genuine factories against the same live enrollment. The connected operation still authenticates the current account and selected note.

Independent source review cleared that limited data contract. These checks do not activate a signing or discard path.

The existing private reservation writer now has a cooperative mode selected by genuine fenced enrollment. It authenticates genuine fenced enrollment before path/storage work, upgrades historical rows without changing their origin, writes v4 and its typed minimum-format floor at the existing floor key, and requires exact ordinary readback. Private receipts and recovery retain their existing shape and exclude relay rows; conflict checks cover both kinds. `assertPrivateAvailable` budgets the two transitions needed by a private reservation and must not be reused as a relay-capacity check.

Original-work retention is an intentional safety fix for both legacy and cooperative stores: closing a store cannot release its same-path writer exclusion while admitted work remains pending. Recovery retains its phase through the original callback and all store work admitted during that callback. Unobservable callback results retain exclusion and any recovery phase until process exit. The contract does not track arbitrary work first started after a callback has settled. Ordinary synchronous callback results and legacy receipt identity are preserved.
