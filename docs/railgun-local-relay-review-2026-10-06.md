# Railgun local fee and peer review

Commit `2c2a343f` adds a main-owned local review of one relay quote against an already-read live Railgun wallet. The selected note, owned record, checkpoint and account generations are rechecked around asynchronous verification and review. A genuine wallet handoff excludes conflicting wallet phases while review is pending. The result records a fee and peer preference; it grants no signing, POI-query, persistence or relay-send permission and has no production receipt consumer.

The four modules live in `src/main/wallet`, which owns wallet authority and process lifecycle. No renderer or IPC surface is added because product interaction remains a later design task. `railgun-relay-quote-data.js` bounds and preserves signed advertisement bytes and computes a capped legacy-gas fee. `railgun-relay-quote-job.js` authenticates the engine archive, decodes the chain-specific address, applies canonical prime-subgroup Ed25519 checks and requires both Noble and Node verification. `railgun-relay-quote-verify.js` owns the guarded public-only utility and original closure. `railgun-relay-review.js` binds the result to the genuine account and an explicit trusted-main review callback. The utility receives no selected note or account payload.

The parser accommodates the inspected upstream format: multiple fee tokens, optional identifier, unknown reliability `-1`, checksummed relay-adapt addresses and service versions 8.0.0 through 8.999.0. These fields confer no operator trust. The selected token remains Freedom's pinned Sepolia WETH; the inspected reference server's default Sepolia token map uses different addresses, so operator support remains unverified. Gas input is explicitly Ethereum legacy type 0. A multiplier of 12000 basis points means 120% of the estimate, or a 20% buffer; the supplied estimate is not verified by this module.

Admission is single-use, with a 15-second verification limit, 30-second callback limit and 45-second overall validity window, further bounded by quote expiry. Closing revokes immediately but retains original pending work. An observed rejected or malformed child-closure barrier fails closure and retains exclusion; a barrier or trusted callback that never settles leaves closure pending. A returned receipt is only a bounded historical local review. A future operation must reattest the account, reserve its inputs and obtain separate authority.
