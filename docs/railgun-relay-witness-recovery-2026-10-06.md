# Original relay witness and pre-transaction POI reconstruction

Utility-only helpers reconstruct the original one-input, fee-first/self-second relay transaction. The existing diagnostic still returns exactly three public fields and its current-root rule is unchanged. Separate fixed fresh/local functions return copied private witness data only inside the utility. Fixed viewing jobs now project bounded public bindings or proof results; private witness material remains inside the utility.

Both paths restore the same current unspent owned note, derive its public key, hash and nullifier, verify the original Merkle path, decrypt both original ciphertexts from the sender side, and check recipients, output types, values, commitments and blinding keys. Local recovery permits the original draft root to differ from the current completed tree root. The fixed local controller authenticates that original draft from durable custody; a self-consistent arbitrary root is not chain acceptance. No transaction is regenerated, repriced, re-encrypted or signed again. Bound parameters retain decoded calldata types, which hash/encode equivalently to the engine constructor's values; they are not a structurally identical constructor object.

The separate pre-transaction POI assembler derives the input blind from the actual input tree/position and reconstructed note. It checks the original required-list event signature/path and note type, derives the TXID leaf using the actual input tree, and constructs the synthetic pre-transaction root with sixteen literal-zero siblings. Fee and self output blinds use the fixed synthetic global position and its successor. Merkle-zero TXID/list padding remains distinct from literal-zero output/path padding.

A keyless checker independently derives the public TXID/root equations and eight POI signals using the pinned Poseidon primitive. It can check the historical event signature and path, but cannot derive hidden output NPKs from commitments. Its blinding, ownership, proof-validity, current-membership and authority flags therefore remain false. The separate fixed proof verifier checks both actual cryptographic proofs against the same original transaction and binding.
