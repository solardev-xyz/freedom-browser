# Original relay witness and pre-transaction POI reconstruction

Utility-only helpers reconstruct the original one-input, fee-first/self-second relay transaction. The existing diagnostic still returns exactly three public fields and its current-root rule is unchanged. Separate fixed fresh/local functions return copied private witness data only inside the utility; no production job exports or admits those returns yet.

Both paths restore the same current unspent owned note, derive its public key, hash and nullifier, verify the original Merkle path, decrypt both original ciphertexts from the sender side, and check recipients, output types, values, commitments and blinding keys. Local recovery permits the original draft root to differ from the current completed tree root. Its future caller must authenticate that original draft from durable custody; a self-consistent arbitrary root is not chain acceptance. No transaction is regenerated, repriced, re-encrypted or signed again. Bound parameters retain decoded calldata types, which hash/encode equivalently to the engine constructor's values; they are not a structurally identical constructor object.

The separate pre-transaction POI assembler derives the input blind from the actual input tree/position and reconstructed note. It checks the original required-list event signature/path and note type, derives the TXID leaf using the actual input tree, and constructs the synthetic pre-transaction root with sixteen literal-zero siblings. Fee and self output blinds use the fixed synthetic global position and its successor. Merkle-zero TXID/list padding remains distinct from literal-zero output/path padding.

A keyless checker independently derives the public TXID/root equations and eight POI signals using the pinned Poseidon primitive. It can check the historical event signature and path, but cannot derive hidden output NPKs from commitments. Its blinding, ownership, proof-validity, current-membership and authority flags therefore remain false. An eventual independent verifier must check both actual cryptographic proofs against the same original transaction and binding.

Root verification passes 126 tests across the core, existing wallet-job contract, assembler and public math suites, plus strict lint and changed-file formatting. Claude cleared the core and Codex cleared the pre-POI helpers; their frozen dependency hashes match the imported sources. Controlled arithmetic/core seams and actual captured event-signature checks are distinguished in tests. No native execution, spending, service query or operation activation follows from these unit results.

The available authentic captured event/path joins a public note vector whose viewing credential is unknown. It supports historical public math replay, but cannot establish the full owned-note assembler success case. Disposable owned-note tests using a substituted service key must remain explicitly synthetic and cannot count as authentic service qualification. The next bounded native experiment therefore checks genuine engine reconstruction and actual tree growth separately from historical public math, with a full-assembler refusal for the mismatched owned note. Full connected signing/proving/recovery, authentic service qualification and external handoff remain open.

The inactive `relay-sign` utility now has its own one-attempt implementation. It validates the canonical zero-proof relay calldata, independently derives the five ordered message inputs, requests one spending credential under a distinct purpose, checks its public key, signs and verifies EdDSA, then wipes the delivered key view before reporting. A refused attempt cannot be retried in the same utility. No process admission, identity loan or controller permit is enabled for this purpose. Twenty-five controlled tests and Claude's source review cover the request/result contract, field order, refusal, abort and key-view wipe paths; these are not real signature qualification. Engine-internal copies are outside that explicit wipe guarantee.

Future host wiring must compare the whole key request against its own authenticated signing record and fresh gates, observe the original utility closure, independently verify the returned signature before filling the write-once slot, and refuse re-signing after any attempted loan. A result followed by job failure must not be accepted as completion. The immutable record digest echoed by the utility supplies no custody or spending authority.

The local proof helpers now consume the canonical signed record, reconstruct its original witness and historical POI binding, and invoke the pinned transaction and POI provers. A separate keyless helper independently verifies both proof domains against the original calldata, signature and historical public equations. It returns exact record, transaction and payload digests; it does not authenticate storage custody or current service membership. Private witness material stays within the producer utility. A bounded record stream carries at most 96 KiB in six indexed chunks, checks the complete digest, and retains original requests through cancellation.

These helpers remain disconnected from production account/signing admission. Root verification passed 245 focused tests across five suites, strict lint and formatting; Codex independently reviewed the frozen helper slice. Controlled prover and runtime seams in these tests do not establish native cryptographic execution. The proposed continuation keeps the existing process and snapshot limits, runs producer and independent verifier serially inside one snapshot callback, and then refreshes public chain evidence before persistence. It must also retain the original callback independently when the coordinator's cancellation race returns early.

The fixed keyless signature job separately recomputes the five-input message and verifies canonical EdDSA before returning exact intent, record and normalized-signature digests. It has no fixed production caller yet. Its future host must supply the spending public key from the authenticated identity descriptor; a key copied from an arbitrary record or producer would not establish identity provenance. The pinned verifier checks curve membership and canonical scalar range, but does not itself establish prime-order public-key provenance. Root passes 109 tests across the signature, signer, canonical signature and relay intent suites, with strict lint and formatting; Claude cleared the frozen source. These controlled tests do not run the real engine cryptography.
