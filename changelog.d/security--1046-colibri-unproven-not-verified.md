- An Ethereum gas price, fee history, balance, nonce, code, storage read, contract call or transaction receipt is no longer marked verified when Colibri didn't prove it for the block or transaction it was asked about ([#1046](https://github.com/solardev-xyz/freedom-browser/issues/1046), [#1060](https://github.com/solardev-xyz/freedom-browser/issues/1060))
  - Colibri can't prove a gas price, a fee history, or a read at the pending or earliest block. It answered them from one of its own built-in public RPC servers, which you never chose, and Freedom labelled that answer verified
  - For a balance, nonce, code or storage read at a past block, by number or hash, Colibri proves the answer from a real block but doesn't check that it is the one asked for. The same goes for the safe, finalized and justified blocks, and for a block named as an object (EIP-1898)
  - Colibri now answers these reads only at the latest block, whose proof it checks is at most a minute old. A read that names no block is asked at the latest one
  - A block looked up by number or hash is still Colibri's, as it checks that block, but not the safe, finalized or justified block
  - Contract calls and gas estimates no longer go to Colibri. It runs them on contract code from one of its built-in public RPC servers, without checking that code
  - The other reads go to the network's RPC servers, as a quorum or a single server, and are labelled as those answers are
  - A transaction receipt from Colibri is used only if it is for the transaction asked about. Colibri looks up where a transaction is from its prover's unchecked index and proves the receipt found there, so a dishonest prover could show a failed send as confirmed. Otherwise the RPC's receipt is shown, labelled as that answer is
